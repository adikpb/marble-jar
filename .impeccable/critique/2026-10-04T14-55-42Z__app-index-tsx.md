#### Overall Impression

Warm, honest, disciplined — and the ledger's integrity is its UX risk. The product handles grief (removals, confirm, undo) with rare care, but the core repeated action (log with the right jar + words + 1 of 7 tags) leans on memory, and a misfiled intimate record cannot be corrected. Fix correctability and recall first; the contrast and composer-placement issues ride along with the same passes.

#### What's Working

1. **Undo that only ever cancels.** Pending removal hides the board for 5s without touching the store; logging to a queued jar keeps it. Matches the shelf metaphor and removes the fear that stops people deleting — critical where a wrong name feels permanent.
2. **Removals as first-class record, not failure.** Equal-weight kept/broke pair, open ring vs filled dot, honey up-bar vs cherry down-bar, darkened struck slip with `−1` meta. PRODUCT.md's "honesty includes removals" survives contact with shame — why someone will actually log a broken promise.
3. **Operable beginnings checklist.** Three rows tick from real shelf state (not localStorage), each linking into the work (focus add / open composer / open top jar), collapsing to a rail when done. Onboarding that does instead of tells, and never desyncs.

#### Priority Issues

- **[P1] No edit or delete for a single marble — What**: Wrong words, wrong tag, tapped Kept instead of Broke can only be repaired by "Add the why" (fills blanks) or an offsetting marble that corrupts the count. **Why it matters**: a ledger whose value is "the moments to back it up" loses trust in the record itself. **Fix**: per-slip edit (words + tag + kept/broke with confirm) and per-slip delete with the same 5s undo idiom as jar removal. **Suggested command**: `/impeccable harden`
- **[P1] Seven-way tag choice with the teaching retired — What**: After the first tagged marble the guide disappears; every later log demands Boundaries-vs-Vault-vs-Integrity recall under time pressure. **Why it matters**: fastest path (logging right after the moment) produces generic Reliability-for-everything or abandonment. **Fix**: keep a one-line gloss visible in the composer (rotate last-used tag gloss), plus long-press any pill for its gloss; never collapse to a single toggle on the task screen. **Suggested command**: `/impeccable onboard`
- **[P1] Working composer lives below the first board once opened — What**: Object-before-tools pushes the log tool a scroll away; position shifts with sort/recent order (`index===0` coupling). **Why it matters**: newcomers learn "Log a moment" in the header, then must re-find it after their first jar; task visits in jar view scroll past vessel + chapters + trend to act. **Fix**: anchor the composer (sticky composer entry or fixed log entry point per screen) independent of shelf order. **Suggested command**: `/impeccable layout`
- **[P1] Solid cherry button text misses AA (4.4:1, needs 4.5:1) — What**: `cream #FBF3E2` on `cherry #C8452C` in `app/index.tsx:1521-1528` (and by construction `app/person/[id].tsx:1044-1051`, unrendered in the probe). **Why it matters**: primary action text on both surfaces fails WCAG AA body threshold; Sam/low-vision users hit it every log. **Fix**: darken cherry for text use or lighten cream until ≥4.5:1, re-verify both buttons in a seeded render; treat `btnSolid` as failing until proven otherwise. **Suggested command**: `/impeccable audit`
- **[P2] Two homes for search/sort + silent preselects — What**: Same state in footer-always and a threshold-gated top cluster at 4+ jars; single-jar auto-target + carried last-tag ("· last time") can misfile with one tap. **Why it matters**: shelf crossing 3→4 jars gains duplicate controls with no announced rule; fast second logs file under the wrong jar/tag with no edit path. **Fix**: one home for tools; make preselects explicit (confirm chip showing jar + tag before Kept/Broke arms). **Suggested command**: `/impeccable distill`
